Собери информацию об синхронных и асинхронных API  этого проекта и бизнес-сущностях, которые принимают или отдают методы API.
Проект содержит папку /specs в корне проекта. Эта папка содержит папки с требованиями и описанием features проекта.
Описания API находятся в файлах, которые расположены в папках /specs/[number-feature name]/contracts/ .
Описания бизнес-сущностей находятся в файлах data-model.md, которые расположены в папках /specs/{number-feature name}/ .
Файлы из папок с большим номером feature может содержать более актуальную информацию информацию об API  и бизнес-объектах, нежели файлы из папок с меньшим номером feature. Если информация об API  или бизнес- объектах противоречит друг другу, то используй для отчета информацию из документации более поздней feature, то есть с большим порядковым номером.

Собранную информацию сохрани в файл ARCH_SCAN.md в формате Markdown. Если такой файл уже существует - перезапиши его.
Следуй строго формату отчета, который описан ниже. Не добавляй дополнительной информации.

** Output Format**

```markdown
# Отчет об обнаружении бизнес-сущностей: [Название микросервиса]


## 1. Внешние API (Синхронные входящие)
| HTTP Метод | API Endpoint | Потребляет (Request DTO/Model) | Производит (Response DTO/Model) | Ключевые бизнес-поля (3-5 атрибутов) |
|------------|--------------|--------------------------------|---------------------------------|--------------------------------------|
| e.g., POST | `/api/v1/orders` | `CreateOrderReq` | `OrderResponse` | `order_id, customer_id, total_amount`|

## 2. Внешние зависимости (Синхронные исходящие)
| Внешняя система / Клиент | Потребляемая сущность (DTO/Model) | Ключевые бизнес-поля (3-5 атрибутов) |
|--------------------------|-----------------------------------|--------------------------------------|
| e.g., `PaymentClient`    | `PaymentStatusDTO`                | `transaction_id, status, timestamp`  |

## 3. Асинхронные события (Event-Driven)
| Направление | Топик / Очередь / Канал | Класс сущности события | Ключевые бизнес-поля (3-5 атрибутов) |
|-------------|-------------------------|------------------------|--------------------------------------|
| Потребление | `inventory.stock.topic` | `StockUpdateEvent`     | `sku, available_qty, warehouse_id`   |
| Публикация  | `order.created.topic`   | `OrderPlacedEvent`     | `order_id, user_id, items`           |

## 4. Основные доменные модели (Внутреннее состояние)
| Класс сущности | Тип хранилища / ORM | Ключевые бизнес-поля (3-5 атрибутов) |
|----------------|---------------------|--------------------------------------|
| `Order`        | Relational (EF Core/JPA/SQLAlchemy) | `id, customer_id, status, created_at`|
```
